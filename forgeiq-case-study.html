1. Executive Summary & Domain Problem

In custom metal fabrication (laser cutting, CNC press brake forming, sheet fabrication), preparing an accurate quotation requires analyzing raw vector CAD files (DXF/DWG). Estimators must manually calculate tool travel distance, inner piercing points, raw sheet utilization percentage, and machine cycle time across various alloys (Stainless Steel 304, Aluminum 6061, Mild Steel).

This manual quoting process takes hours and creates significant delays between buyers and fabrication plants. When building ForgeIQ, the goal was to automate this entire workflow end-to-end: parse technical CAD files deterministically, compute quotations with 96.9% accuracy, and track confirmed orders across a 9-stage shop-floor pipeline.

2. Core Architecture: Deterministic Math vs. AI Hallucination

A common trap in Generative AI development is feeding technical drawing renders directly to vision LLMs. Because LLMs are probabilistic models, they frequently hallucinate physical dimensions, confuse millimeters with inches, and miss micro-piercing holes—which produces disastrous pricing errors for manufactured physical goods.

The Architectural Solution: Strict Boundary Separation

ForgeIQ strictly separates mathematical geometric computation from natural language processing. Geometry is 100% deterministic (Python + ezdxf), while NLP is strictly confined to unstructured buyer RFQ notes, tolerance callouts, and material surface finish requirements.

The 3 Root Causes & Solutions:

1. Database Query Roundtrip Bloat (N+1 Issue)

Order tracking queries previously fetched order parent rows, then executed separate queries for stage transition history and line items. Refactored into unified Common Table Expressions (CTEs) with composite B-Tree indexes on (tenant_id, order_id, stage_timestamp), reducing query roundtrips from 12 down to 1.

2. Geometry Vector Cache Invalidation

Repeated requests for the same standardized CAD bracket drawings re-triggered vector disk I/O. Added SHA-256 fingerprinting of incoming DXF file streams to store pre-computed feature records in an in-memory Redis cache with TTL invalidation.

3. Asynchronous Event-Loop Thread Starvation

Calculating complex polygon intersections is CPU-bound and blocked FastAPI's main async event loop. Offloaded geometric computations into a dedicated ProcessPoolExecutor, preserving immediate responsiveness for concurrent HTTP network I/O.

5. Automated Verification & Testing Discipline

To ensure high-concurrency optimizations caused zero regressions, the entire application is backed by automated suites:

33 Pytest Tests (100% Passing)

Verifies DXF entity geometry extraction, closed contour boundaries, parametric pricing equations, and HTTP error response schemas.

14 Playwright E2E Tests

Simulates real browser workflows: user sign-in, multi-file DXF upload, instant quotation calculation display, and order stage progression in the customer portal.
